WhiteCarrot Architecture & Routing Blueprint

A complete deep-dive into the Next.js 15 App Router architecture, folder responsibility, code transitions, and feature execution lifecycles.

🛠 Core Tech Stack

Framework: Next.js 15 (App Router)

Database: PostgreSQL + Prisma ORM

Authentication: NextAuth.js (Auth.js)

Styling: Vanilla CSS + Tailwind + Shadcn UI

Validation: Zod Schemas

🚦 Routing Paradigms

Route Groups: (auth), (dashboard), (public)

Dynamic Routes: /company/[companySlug]/...

Protection: Edge Middleware middleware.ts

Data Mutation: Server Actions in lib/actions/

💡 Architectural Benefits

Separation of Concerns: Server logic in lib/, UI in components/, routes in app/.

Security: DB queries execution strictly on Node.js Server runtime.

Performance: Instant client updates via Next.js cache revalidation.

📁 Complete Directory & File Guide

Every directory in this project has a specific structural responsibility:


  • app/ Next.js App Router root containing pages, layouts, and API routes
    • (auth)/ Route Group Authentication pages (URLs do NOT include "(auth)")

    • (dashboard)/ Route Group Protected Recruiter Admin Experience
      • layout.tsx Dashboard sidebar & header navigation layout

        • preview/page.tsx Recruiter draft preview mode
    • (public)/ Route Group Public candidate career portal
      • [companySlug]/careers/
        • page.tsx Public candidate career page site
    • api/ REST endpoints
      • auth/[...nextauth]/route.ts NextAuth session handler
      • upload/route.ts File upload handler (logos, banners, resumes)

  • components/ React Client & Server UI Components
    • candidate/ Job listings cards, search filters, application modal
    • editor/ Drag-and-drop section panels, style controls, theme pickers
    • navigation/ Header, Recruiter Navbar, Footer components
    • preview/ Section renderers (Hero, Culture Video, Open Roles, Perks)
    • ui/ Atomic UI components (Button, Dialog, Input, Select, Switch)

  • lib/ Core Logic, Infrastructure & Utilities
    • actions/ Next.js Server Actions (Database CRUD operations)
      • careers-page.ts Draft saving, section reordering, publishing logic
      • company.ts Company profile creation & updates
      • jobs.ts Job creation, editing, status changes
      • applications.ts Candidate application submissions
      • public.ts Public data fetching for candidate career site
    • db.ts Prisma Client singleton instance connection
    • auth.ts NextAuth options, password hash verification, session callbacks
    • validators/ Zod schemas for form & payload verification

  • middleware.ts Edge middleware intercepter for route authentication checks

🚦 Next.js Routing Mechanics & Protection

Here is exact flow when an HTTP request enters the application:

User Requests URL → Edge Middleware (middleware.ts) → Route Group Matching → Layout Wrap → Page Render
Requested Path Matched File Middleware Action Render Output
/login app/(auth)/login/page.tsx Passes through Login Form
/dashboard app/(dashboard)/dashboard/page.tsx Checks authjs.session-token cookie. If missing → Redirects to /login Recruiter Dashboard
/acme/careers app/(public)/[companySlug]/careers/page.tsx Passes through (Public) Published Careers Page for "acme"
/company/acme/design app/(dashboard)/company/[companySlug]/design/page.tsx Protected → Requires Auth No-Code Studio Editor

🔁 Step-by-Step Code Transitions for Core Features

1. Recruiter Authentication Flow

1

User Fills Credentials Form

File: app/(auth)/login/page.tsx

User enters email & password and submits form. Clicking "Sign In" invokes signIn('credentials', { email, password }) from NextAuth.

2

Authentication Verification

File: lib/auth.ts via app/api/auth/[...nextauth]/route.ts

NextAuth calls the authorize() callback inside lib/auth.ts. It uses Prisma (lib/db.ts) to query the User record and verifies password hash using bcrypt.

3

Session Cookie Creation & Redirect

File: middleware.ts & NextAuth Engine

An encrypted JWT session cookie is attached to the browser response. Next.js router navigates to /dashboard.

2. Career Page Design Studio (No-Code Builder Flow)

1

Studio Page Initialization

File: app/(dashboard)/company/[companySlug]/design/page.tsx

A Server Component fetches initial draft sections and company preferences using getCareersPageDraft(companySlug) from lib/actions/careers-page.ts.

2

Interactive Drag & Style Control

Files: CareerStudioClient.tsx & components/editor/panels/SectionStylePanel.tsx

Recruiter re-orders sections or edits colors. React state updates locally for instant 60fps responsiveness.

3

Live Canvas Rendering

File: components/preview/CareersPageRenderer.tsx

The right canvas dynamically loops through sections array and renders corresponding section components (e.g., HeroSection, CultureVideoSection, OpenRolesSection).

4

Saving & Publishing to Database

File: lib/actions/careers-page.ts

Clicking "Publish" executes Server Action publishCareersPage(). It marks sections as isPublished: true in PostgreSQL and calls revalidatePath('/[companySlug]/careers') so candidate visitors immediately see live updates.

3. Candidate Job Search & Application Flow

1

Candidate Views Public Careers Site

File: app/(public)/[companySlug]/careers/page.tsx

Calls getPublicCareersPage(companySlug) in lib/actions/public.ts. Fetches published page sections, active jobs, and company branding.

2

Opening Application Form

Files: components/candidate/JobCard.tsx & ApplicationModal.tsx

Candidate filters jobs by department/work mode and clicks "Apply". Modal renders application input fields (Name, Email, Resume URL, Cover Letter).

3

Submitting Application

File: lib/actions/applications.ts

Form submission triggers Server Action submitApplication(). Validates data with Zod, creates Application row in Prisma DB, and returns success confirmation.

🧠 Architectural Rationale: Why `lib/`, `components/`, and `app/`?

Why `lib/` directory?

Contains pure non-UI TypeScript logic. Keeping database queries (Prisma), server actions, authentication logic, and schemas inside lib/ ensures:

  • Strict separation between UI presentation and data persistence.
  • Server Actions in lib/actions/ can be safely called from any Client Component.
  • Prevents accidental leaking of backend secrets to the browser.

Why `components/` directory?

Holds reusable React components divided by domain (candidate, editor, preview, ui):

  • Modular component design reduces bundle size.
  • components/ui/ contains low-level primitives (Buttons, Dialogs) isolated from business logic.
  • Easier maintenance when updating specific feature UI without breaking page routes.

Why Next.js App Router (`app/`)?

Leverages Next.js 15 route groups and nested layouts:

  • (auth), (dashboard), and (public) provide dedicated layouts without bloating URLs.
  • Server Components by default allow instant streaming and fast SEO page loads.
  • Edge middleware provides centralized route security.
